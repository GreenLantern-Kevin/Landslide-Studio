LandslideStudio 使用指南

本指南按“准备环境—配置模型—提交分析—核对结果”的流程介绍本地工作台。四个分析模块可独立使用，按研究任务准备相应依赖和模型即可。

安装与启动 · 模型与 API 配置 · 影像合成 · 语义分割 · 视频分析 · 辅助报告 · 结果与维护 · 常见问题

1. 安装与启动

1.1 选择运行环境

在 Windows 上安装 Python 3.10，并包含 Windows Python Launcher。将仓库解压到固定目录，以下脚本均从工作台根目录运行。

使用需求 安装步骤
浏览界面、光流分析、API 报告 运行 01_安装基础环境.cmd
NVIDIA GPU 影像合成或分割 先安装基础环境，再运行 02_安装AI环境.cmd
CPU 影像合成或分割 先安装基础环境，再运行 02b_安装CPU推理环境.cmd

GPU 脚本安装 PyTorch 2.7.1 / torchvision 0.22.1 的 CUDA 12.6 版本，需要兼容的 NVIDIA 驱动。CPU 可以运行推理，但较大模型与影像的处理速度受硬件限制。

1.2 创建个人配置

将 .env.example 复制为 .env，将 config.example.json 复制为 config.local.json。前者保存 API 密钥，后者设置模型位置和推理参数。示例中相对路径以工作台根目录为基准。

基础模型、LoRA、分割权重、API 密钥、数据集和个人结果不包含在源码仓库中。修改个人配置后，通过“模型与配置”页面刷新状态；安装或更换依赖后应重新启动服务。

1.3 启动、检查与停止

  1. 运行 00_启动平台.cmd。
  2. 在浏览器打开 LandslideStudio。
  3. 查看“模型与配置”页面；如需检查依赖和模型文件，运行 04_环境自检.cmd。
  4. 结束使用时运行 03_停止平台.cmd。

“已放置”表示文件存在，模型能否加载仍取决于结构、内容和训练配置是否匹配。关闭浏览器不会停止后台服务。

2. 模型与 API 配置

2.1 基础模型和 LoRA

基础模型按以下约定存放，均需为完整 Diffusers 目录，包含 model_index.json 和对应组件：

页面选项 基础模型目录 对应 LoRA 目录
Stable Diffusion 1.5 models/base/sd15/ models/lora/sd15/
Stable Diffusion 2.1 models/base/sd21/，下载版本为 768 models/lora/sd21/
Stable Diffusion XL models/base/sdxl/，SDXL Base 1.0 models/lora/sdxl/

运行 07_下载或续传基础模型.cmd 可下载或续传基础模型。来源和固定版本记录在 scripts/model_sources.json。只下载一个模型时，在已安装的环境中运行，例如：

.venv\Scripts\python.exe scripts/download_base.py sdxl

在每个 LoRA 目录内，分别放入与该基础模型匹配的 Southwest_China_Landslide.safetensors 和 Southwest_China_Terrain.safetensors。两者对应滑坡和非滑坡类别。文件名相同不代表权重通用；模型家族、版本和训练配置应匹配，尤其需要区分 SD 2.1 的训练版本。

下载脚本不提供个人 LoRA 或分割权重。使用前应核对各模型来源及许可条件。

2.2 分割权重

默认权重位置为 models/segmentation/m2f_deeplab.pth。使用 M2F-DeepLab 训练完成的权重，推荐完整 checkpoint，以保留网络名称、输出步长、类别数、评估尺寸等元数据。

默认模型为完整 E 模型 m2f_deeplabv3plus_xception16，num_classes=2、separable_conv=false；未记录输出步长时，使用配置默认值 output_stride=16。架构设置必须与训练一致，不能通过任意修改参数消除加载错误。

“滑坡语义分割”页面的“检查权重可识别的参数”可读取 checkpoint 元数据；也可在命令行检查：

.venv\Scripts\python.exe scripts/inspect_weights.py models/segmentation/m2f_deeplab.pth

检查结果区分明确记录的参数与从已知输出层形状识别的信息。输出步长、训练裁剪尺寸和地形通道编码不能仅凭卷积权重形状可靠推断。有关页面参数和输入要求，见本页语义分割。

2.3 上海交通大学致远一号AI模型API

在 .env 中设置 SJTU_API_KEY；在 config.local.json 的 llm 中填写服务地址和账户可访问的模型 ID。按模型实际能力设置 supports_vision：需要直接分析影像时，必须选用支持图像输入的模型。

示例模型 ID 不保证对所有账户开放。连接失败时，核对密钥、模型权限、服务地址以及校园网络或 VPN 条件。不要将 .env、个人配置或密钥提交到源码仓库。

3. 遥感影像合成

  1. 选择已准备好的基础模型和影像类别。
  2. 输入场景提示词，可描述地形、植被、光照及俯视角度。
  3. 设置输出尺寸和数量；首次使用可从较小尺寸、单张输出开始。
  4. 按需调整采样步数、CFG、LoRA 强度和随机种子，然后提交任务。
  5. 核对生成影像并下载结果，保存生成参数以便比较。

类别会自动加入对应激活词：滑坡为 Southwest_China_Landslide，非滑坡为 Southwest_China_Terrain，无需重复填写。固定随机种子有助于对照参数变化，-1 表示随机种子。

合成影像用于研究和数据探索，不代表真实观测。比较不同实验时应同时记录基础模型、LoRA、尺寸、种子和提示词。

4. 滑坡语义分割

4.1 准备输入

RGB 输入应为与训练预处理一致的 8 位影像。RGB TIFF 默认使用第 1、2、3 波段作为红、绿、蓝，不会对高位深影像自动拉伸。

DEM 为可选输入，必须是训练流程制作的 uint8 三通道高程/坡度/坡向地形图。保留训练时的文件解码通道顺序与像素编码，不要将原始单波段高程、任意灰度图或视觉相似的伪彩色图片替代该输入。RGB 与地形图均按 ImageNet 均值和标准差归一化。

RGB 与 DEM 需要逐像元配准。带地理参考的文件会核对 CRS、仿射变换和尺寸；普通图片必须具有一致的尺寸、覆盖范围、方向及像元位置，并由使用者勾选配准确认。尺寸相同本身不能证明配准正确。

4.2 选择输入路径

输入与模型 实际处理路径
RGB+DEM、双流模型 显式 has_dem=True，使用真实地形特征
仅 RGB、完整 E 模型 显式 has_dem=False，使用 FHM 特征补全
仅 RGB、B 变体 使用零地形特征
A 变体 RGB 单流，需要对应训练权重

RGB-only 使用相应网络的缺失模态推理能力，效果取决于权重训练；上传 DEM 不会自动将 RGB 单流权重转换成双流模型。

4.3 设置输出步长与推理尺寸

默认保留自动选项。平台优先读取 checkpoint 明确记录的参数；没有步长记录时，使用配置值 16。手动选择步长 8 或 16 必须与训练一致，与已有记录冲突会停止运行。

影像处理方式 行为 适用场景
自动 auto 读取 eval_resize / val_size；缺省为 256，值为 0 时按原图推理 复现 checkpoint 的评估尺寸约定
原图 native 不缩放、不分块，忽略窗口尺寸和重叠 需要保留输入尺寸且显存足够
缩放 resize 整图缩放到指定正方形尺寸，推理后恢复原尺寸 明确使用统一评估尺寸
滑窗 tiles 分块推理并融合重叠区概率 大图或显存受限

窗口/缩放尺寸可留空自动读取；手动输入须为 64–1024 的整数，无需是 16 的倍数。滑窗重叠须大于等于 0 且小于窗口尺寸。自动模式下手动填写尺寸，会在本次任务中使用该尺寸缩放。

crop_size 是训练裁剪参数，不等同于 eval_resize / val_size。改变尺寸或改用滑窗可能改变结果，比较实验时应保持策略一致。

4.4 提交与核对结果

上传 RGB 和可选地形图，完成必要的配准确认，设置叠加透明度后提交。先查看原图与叠加图的空间对应关系，再核对掩膜和统计。

输出 解释
mask.png 0 为背景或无效像素，255 为滑坡候选像素
valid_mask.png 255 为有效像素；用于区分背景和无效区域
overlay.png 在 RGB 上标出候选区域
probability.npy、probability.png 原始滑坡类别概率与预览；原始数组的无效像素为 NaN
metrics.json 输入、有效参数及来源、模态路径、加载信息和区域统计
mask_geo.tif 有地理参考时导出，0 为背景、1 为滑坡、255 为无效值

候选面积默认以像素数和有效区域占比表示；仅在具备可用投影和长度单位时计算平方米。概率未经校准，像素占比不等于滑坡发生概率。没有真值标签时不计算准确率、IoU 或 F1。

4.5 权重兼容范围

平台使用 weights_only=True 读取权重，逐项检查推理参数名称与形状，并以 strict=True 加载。对于明确记录默认 Xception16 架构、步长 8/16、两类且 separable_conv=false 的 schema 2 checkpoint，只有全部 1674 项推理参数一致、并且仅多出八项形状完全匹配的训练辅助头参数时，才在内存中排除该辅助头后严格加载。原权重文件保持不变。

其他缺失、未知或形状不符的参数会报错。该规则不是通用部分加载，也不保证所有训练版本或 checkpoint 兼容。源码仓库中的“分割推理说明”提供完整参数约定与辅助头形状清单。

5. 滑坡视频分析

5.1 选择算法和分析范围

稀疏光流采用 Lucas–Kanade 跟踪特征点，提供双向一致性检查、周期补点与轨迹筛选；稠密光流采用 Farnebäck 估计图像区域内的运动向量。两者的采样方式不同，统计量应在同一算法和参数条件下比较。

  1. 上传视频，选择算法和运动噪声阈值。
  2. 按需限制 ROI；坐标以处理画面的比例表示，左上角为 (0, 0)。
  3. 如启用背景特征防抖，在 ROI 外保留足够的静态背景。
  4. 默认按原始尺寸处理；高分辨率视频可选择限制最大宽度，保持长宽比且不放大。
  5. 提交任务，检查分析视频、轨迹及逐帧记录。

5.2 调整可视化

稀疏模式的轨迹长度控制保留的运动历史，最小净位移决定何时绘制轨迹，补点间隔决定更新频率。轨迹不明显时，应先核对运动尺度与这些阈值。

稠密模式的向量采样间隔控制显示密度，箭头长度倍率和运动幅值显示增益增强可视化，不改变计算速度。处理结果支持任意帧速度分布图及原图叠加，可结合逐帧数据查看局部运动。

5.3 解释输出

分析视频采用四宫格，宽、高分别为处理画面的两倍，导出视频不保留原音轨。速度以处理分辨率下的 px/s 表示；缩放会改变像素位移与速度数值，跨任务比较时需保持处理尺寸、帧率和参数一致。

空间尺度和相机几何未标定时，不应将 px/s 当作 m/s。相机运动、光照、植被和遮挡均可能影响光流；防抖失败或无有效测量不能解释为地表静止。光流能量为位移平方和，不是物理动能，稀疏与稠密结果不能直接比较能量大小。

6. 辅助分析与报告生成

6.1 选择证据和分析方式

可上传影像、关联已完成的分割或视频结果，并填写现场背景与关注问题。关联结果应来自同一场景；如需先计算候选区域，可选择对本次影像运行 RGB 分割。

模式 使用依据 是否调用 API
图像解读 本次影像、关联指标和备注 是；需要视觉模型，并勾选本次发送影像
证据报告 关联指标和备注，不发送图片 是；使用文本能力
本地证据摘要 已有程序计算结果和备注 否

视觉模式还要求 supports_vision=true。文本模式没有看到影像，不能据此声称观察到裂缝、植被或裸土等视觉特征。本地摘要会明确说明未调用大模型；文本报告会明确说明没有接收影像。API 调用失败时，应查看错误原因，修正配置后重新提交。

6.2 核对报告

报告应区分程序计算结果、未经核验的现场描述、视觉观察、推断与未知项。核对其中的数值是否与关联结果一致，并保留模型与人工判断之间的差异。

单幅影像不能确定滑坡发生时间、运动速度、诱因或未来失稳概率。像素尺寸不是地面空间分辨率；缺少可靠标定时，报告中的像素统计不能替代实地面积或风险判断。

7. 任务、结果与环境维护

四个模块均支持可选任务名称。留空时显示模块名称，填写后显示“模块名称-任务名称”；可在“任务与结果”中重命名并重新打开结果。

输入、结果和报告保存在 data/jobs/，缓存位于 .cache/，日志位于 logs/。视频与逐点记录可能占用较大空间。清理前运行 03_停止平台.cmd，备份所需数据，再删除不再需要的任务目录；删除目录会一并移除其中的输入和结果。

迁移到其他电脑或虚拟环境失效时，运行 06_迁移后重建环境.cmd 重新创建 .venv，再检查模型文件和个人配置。不要将已有 .venv 视为跨电脑通用环境。服务面向本机使用，未提供公网账户认证或多用户权限管理。

8. 常见问题

现象 检查与处理
提示缺少基础或 AI 依赖 按所用功能运行对应安装脚本，完成后重启服务
基础模型已下载但不能加载 检查是否为完整 Diffusers 目录、下载是否完整，以及 LoRA 是否匹配
分割权重结构不匹配 核对网络版本、模型名称、类别数、可分离卷积设置及完整 checkpoint；不要跳过严格校验
无法安全读取 checkpoint 保留 weights_only=True；在可信训练环境中导出纯参数字典，并单独保留可用元数据
分割步长冲突 使用 checkpoint 记录的 8 或 16；未记录时从训练配置确认，不从张量形状猜测
DEM 类型或配准检查失败 使用训练格式的三通道 uint8 地形图，并在 GIS 中完成配准
分割显存不足 使用滑窗，例如窗口 256、重叠 64；同时检查其他程序的显存占用
GPU 不可用 核对驱动与 CUDA 版 PyTorch；无适用 GPU 时安装 CPU 环境
API 报告失败 查看原因，核对密钥、服务地址、模型权限、视觉能力和网络条件
关闭网页后服务仍在运行 运行 03_停止平台.cmd
